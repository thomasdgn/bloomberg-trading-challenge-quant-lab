# GTC Digital Twin — Decision Lab

**Independent research sandbox. No model, order, branch main or Bloomberg/TMSG account changes.**

This branch is based on **feature/gtc-live-ops-audit-20261020**, which supplies verified holdings, cash, FX and strict asset eligibility checks. It is **not** based directly on main. Open the PR against that parent branch to review only this work.

## What it does

Three matched, counterfactual *buy-and-hold* simulations from the verified current holdings to **13 November 2026**:

- **HOLD:** leave the confirmed TMSG holdings and USD cash unchanged.
- **REBALANCE:** evaluate your independently specified long-only allocation. It does *not* generate model picks or automatically place orders.
- **DEFENSIVE:** multiply current equity weights by an explicit factor in [0,1); hold the rest in USD cash. This is lower *equity exposure*, not guaranteed lower tracking error or higher return.

Each scenario starts at the same observed portfolio value, trades at idealized marks, and pays a one-off assumed transaction cost proportional to one-way turnover. Positions then drift **without any future rebalancing**, over the same future market paths generated by a **paired moving-block bootstrap** of *historical, jointly aligned, USD-denominated daily returns* for the selected assets and **actual WLS Index**. Blocks capture some serial and cross-asset structure; repetitions are not new independent information.

The outputs report 10th/50th/90th percentile *WLS-relative terminal wealth*, the simulated fraction of paths beating WLS, downside relative drawdown, current cash/equity allocations, initial turnover and paired improvement versus HOLD. **These fractions are not calibrated forecasts, not probabilities of winning the challenge, and not evidence of alpha.** A historical sample for today's selected universe is subject to survivorship/selection bias; no return distribution can prove you can finish top 1.

An offline **HTML dashboard** explains the counterfactuals. A private **Decision Journal** seals the selected scenario, contemporaneous scenario summaries and SHA-256 input fingerprint before outcomes occur, then records periodic realized TMSG checkpoints and a final 13 November result. This supports prospective accountability, not causal attribution to the simulated trade.

## Private production input contract

Supply one local JSON file under `outputs/gtc_twin/`. **Never commit real holdings, TMSG exports, licensed Bloomberg prices or credentials.** `outputs/` is already Git-ignored. The file contains:

- `decision_cutoff`: ISO decision day, identical to the snapshot valuation date.
- `snapshot`: executed TMSG positions, reconciled USD cash, all potential candidate instruments, verified WLS-equity membership, local price/unit, conversion USD per major currency unit, dated price and FX; `pending_orders=[]` mandatory for a simulation. See `docs/gtc_live_operations.md` for full contract. No submitted orders are assumed filled.
- `rebalance_weights`: dictionary of **all desired nonzero equity weights**, plus explicit `USD_CASH`; sum exactly to 1, no shorts, max 20% per equity, unlisted positions implicitly zero. The strategy **does not** infer an optimum: teams must provide externally researched weights.
- `defensive_equity_scale`: e.g. `0.50`; a simple shrink of every current equity weight. This may underperform WLS in an up market.
- `assumed_execution_cost_bps`: an explicit assumption, **not** the official fee schedule. A trade at the mark is optimistic, especially for illiquid titles and unfilled limits. Slippage and commission are aggregated in this single one-off rate.
- `bootstrap_paths` 200–5000; `seed` integer; `block_size_sessions` 1–20.
- `verified_exchange_sessions`: strictly sorted, full verified US exchange calendar including decision day and ending on 13 November; only dates **after** decision day are simulated. Other exchange holidays and cross-market trading must also be checked outside this module.
- `data_verification`: `verified_by_operator:true`, `basis:"SPLIT_ADJUSTED_PRICE_RETURN_USD"`, `benchmark_id:"WLS Index"`, `selection_policy:"AS_OF_VERIFIED"`, `validated_at` within seven days of decision, plus informative `source`. It is an *attestation*, not Bloomberg authentication.
- `history`: **at least 80** dated, strictly pre-decision, common daily rows; for each date include `date`, numeric `wls` daily return and `returns` mapping **every instrument in snapshot** to a numeric daily USD return. History's last point must not be more than seven calendar days old; no proxy benchmark, implicit fills, FX-forward substitution, missing data filled as zero or future returns allowed.

All historical WLS and equity inputs must use consistent **split-adjusted price returns in USD**, with correct per-date FX and price-unit scaling (e.g. GBp versus GBP), documented methodology and point-in-time availability. Cross-currency return conversions must happen **before** input; the Twin deliberately does not fabricate them. Check market holidays carefully for Asian equities on NYSE days. Today-selected constituents backfilled historically still introduce survivorship bias.

A stale repository benchmark (last known 7 October) is **not acceptable** at 21 October. Obtain the current WLS export and a real joint historical market panel before interpreting results.

## CLI commands

```powershell
python -m tools.gtc_twin simulate --input outputs/gtc_twin/private-input.json --output outputs/gtc_twin/run-20261021-001

python -m tools.gtc_twin record-decision --report outputs/gtc_twin/run-20261021-001/simulation.json --chosen HOLD --note "No orders assumed" --journal outputs/gtc_twin/decision_journal.jsonl

python -m tools.gtc_twin verify-journal --journal outputs/gtc_twin/decision_journal.jsonl

python -m tools.gtc_twin record-checkpoint --input outputs/gtc_twin/checkpoint.json --journal outputs/gtc_twin/decision_journal.jsonl

# Only after verified competition end (13 Nov 2026):
python -m tools.gtc_twin record-final --input outputs/gtc_twin/final.json --journal outputs/gtc_twin/decision_journal.jsonl
```

Checkpoint/final JSON:

```json
{
  "run_id": "EXACT_ID_FROM_SIMULATION_JSON",
  "observation_date": "2026-10-22",
  "verified_by_operator": true,
  "source": "Official TMSG report, verified by team",
  "benchmark_id": "WLS Index",
  "portfolio_return": 0.012,
  "wls_return": 0.009
}
```

Returns are **fractional, cumulative since decision date**, not percentages, and must represent the same window and price-return basis. This sample is fabricated. Checkpoints are limited to days *strictly before* the 13 November deadline: they **do not** compare a partial-period actual return with a full-horizon forecast. A final outcome is only accepted for a verified 13 November observation and after that day has arrived. The journal is append-only, verifies every SHA-256 link and blocks duplicate outcomes. Hash chaining can detect accidental alterations but **cannot prove authenticity or prevent a sophisticated complete rewrite**; archive an independent digest if required.

## Robustness grid: detect a fragile decision

The optional `sensitivity` command evaluates a research grid of cost assumptions
and moving-block lengths, using the same verified input panel. It writes a private
JSON file below `outputs/gtc_twin/`, refuses overwrite, and reports each
scenario's median WLS-relative outcome and its paired difference from HOLD.

A unique winner is counted only when its median differs materially from alternatives;
ties are explicitly recorded. **Winner counts across grid cells are NOT independent
trials and not a probability that a strategy will win**: the same historical returns
are resampled repeatedly. If a proposed rebalance appears favorable only with
negligible costs or one bootstrap block, the conclusion is fragile and should
not trigger any automatic order.

## Security, scope and review limitations

- No market data fetching, Bloomberg terminals, bank authentication, TMSG API, brokerage orders, background monitoring, web server or secrets.
- No numerical claim that any scenario improves expected ranking or wins the challenge.
- No automatic integration into existing Elastic Net, Tail, covariance, main 80/20 pipeline or macro research branches.
- Cannot reconstruct missing official WLS members, corporate actions, historical FX, price units, partial fills, impact or cash flow.
- Use the live-ops `session` gate for proposed real orders separately; a successful Twin run is never an execution authorization.
- If the historical panel is too thin, the input is invalid or the official benchmark is stale, **stop rather than relax constraints**.

## To progress from research to live decision support

1. Obtain a fresh Bloomberg WLS level and verified historical USD-adjusted WLS/asset series and FX provenance.
2. Reconcile official executed TMSG positions, cash and order states, then prepare realistic candidate target weights.
3. Re-run paired scenarios under sensible cost and block-length sensitivity checks; inspect the error bars.
4. Record the *decision before execution*, then independently verify subsequent realized P&L and actual fills.
5. Only implement any new trading policy after separate out-of-sample validation of signal and execution mechanics.
